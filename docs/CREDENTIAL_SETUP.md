# Connect the accounts

The local `.env` already contains the OpenRouter endpoint, a currently listed free model, FFmpeg paths, video settings, and empty credential fields. `.env` and `.secrets/` are ignored by Git. Put secret values in those local files, not in a commit or chat message. Run `.\.venv\Scripts\python.exe -m shorts check` after each step; it reports presence without printing secret values.

## 1. OpenRouter: script generation

1. Sign in at [OpenRouter API keys](https://openrouter.ai/settings/keys), create a key, and copy it when shown.
2. Put it after `LLM_API_KEY=` in `.env`. Keep `LLM_BASE_URL=https://openrouter.ai/api/v1` and `LLM_MODEL=google/gemma-4-26b-a4b-it:free` unless you choose another listed model. Set `LLM_FALLBACK_MODEL=nvidia/nemotron-3-super-120b-a12b:free` to use a specific free model with JSON output when Gemma's provider is rate limited. [OpenRouter's fallback routing](https://openrouter.ai/docs/guides/routing/model-fallbacks) tries it after the primary model. The [quickstart](https://openrouter.ai/docs/cookbook/get-started/quickstart) describes the key and endpoint.
3. Generate with a pasted script if you want to test the rest of the pipeline before getting a key.

## 2. YouTube: OAuth upload access

1. Use a Google account with a YouTube channel. In [Google Cloud Console](https://console.cloud.google.com/), create/select a project and enable **YouTube Data API v3**. In **Google Auth platform → Overview**, complete **Get started** with an app name and your support/contact email. In **Audience**, choose External if you use a personal Google account; while the app is in Testing, add the Google account that owns the channel as a test user. In **Data Access**, add the `https://www.googleapis.com/auth/youtube.upload` and `https://www.googleapis.com/auth/youtube.readonly` scopes. The upload scope sends videos; the read scope checks their processing and privacy status. [Google's Auth Platform guide](https://support.google.com/cloud/answer/15544987) and [Data Access guide](https://support.google.com/cloud/answer/15549135) describe these screens.
2. In **Google Auth platform → Clients**, create an **OAuth client ID** with application type **Desktop app** and download its JSON. Save it as `D:\Shorts\.secrets\client_secret.json` (the filename must match `YOUTUBE_CLIENT_SECRET_FILE` in `.env`). [Google's Desktop client instructions](https://developers.google.com/workspace/guides/create-credentials#desktop_app) cover these steps.
3. Run `.\.venv\Scripts\python.exe -m shorts auth-youtube`. Sign in to the correct Google account and grant the upload and read scopes. This creates `.secrets/youtube-token.json`. If you previously granted only the upload scope, run this command again to replace the token. [Google's installed-app OAuth guide](https://developers.google.com/youtube/v3/guides/auth/installed-apps) explains the consent flow. This project does **not** need a separate `YOUTUBE_API_KEY` for uploading.
   If the app is **External** and its publishing status is **Testing**, add your Google account as a test user before authorizing. Google says these authorizations expire after seven days, so move the OAuth app to a suitable production state before relying on unattended long-term publishing. See [Google's audience guide](https://support.google.com/cloud/answer/15549945) and [refresh token rules](https://developers.google.com/identity/protocols/oauth2#expiration).
4. First uploads should use `youtube=private` so you can inspect them. Google may restrict uploads from unverified API projects; see the [videos.insert documentation](https://developers.google.com/youtube/v3/docs/videos/insert).

## 3. Facebook Page and Instagram professional account

1. [Create a Facebook Page](https://www.facebook.com/pages/create) for the channel using the Facebook account that will manage it. Create an [Instagram account](https://www.instagram.com/accounts/emailsignup/) if needed, switch it to a **professional Business or Creator account**, and connect it to that Page from the Instagram profile's **Edit profile → Page** controls. This project's Instagram adapter uses [Meta's Facebook Login flow](https://www.postman.com/meta/instagram/folder/u4g5a2a/instagram-api-with-facebook-login), which requires a professional account linked to a Page.
2. Create a Meta developer app at [My Apps](https://developers.facebook.com/apps/). Meta's [Instagram API collection](https://www.postman.com/meta/instagram/collection/6yqw8pt/instagram-api) recommends a Business app for this Facebook Login flow. In [Graph API Explorer](https://developers.facebook.com/tools/explorer/), select that app and generate a **User Access Token** with `pages_show_list`, `pages_read_engagement`, `instagram_basic`, and `instagram_content_publish`, as listed in [Meta's Instagram collection](https://www.postman.com/meta/instagram/folder/u4g5a2a/instagram-api-with-facebook-login). Also request `pages_manage_posts` for Facebook Page publishing. If the Page is linked to a Meta Business account, request `business_management` too and ensure the same Facebook user has a role on that business; otherwise `/me/accounts` omits the Page ([Meta Graph API changelog](https://developers.facebook.com/docs/graph-api/changelog/non-versioned-changes/nvc-2023/)). Grant access to the Page and linked Instagram account, then generate and copy the new token. If the Instagram permissions are absent in Graph API Explorer, check the app dashboard for the Instagram Graph API setup that uses Facebook Login. App mode, Page tasks, and permission review can affect access.
3. With the authorized User Access Token, use Meta's [Get Access Tokens of Pages You Manage](https://www.postman.com/meta/instagram/request/lpx8lul/get-access-tokens-of-pages-you-manage) request. Choose your Page and copy its `id` to `META_PAGE_ID`, `access_token` to `META_PAGE_ACCESS_TOKEN`, and `instagram_business_account.id` to `INSTAGRAM_USER_ID` in `.env`. If the Instagram ID is absent, check the professional-account/Page link. The [Facebook Page Reels collection](https://www.postman.com/meta/facebook/documentation/r56bjfd/facebook-api?entity=request-23987686-0b79260c-96bd-49de-875b-6076213785fc) uses the same Page token for uploads. A Page token derived from a short-lived Graph API Explorer User token can expire in hours. For unattended publishing, [exchange that User token for a long-lived User token with your app ID and secret](https://developers.facebook.com/docs/facebook-login/guides/access-tokens/get-long-lived/), then get a new Page token from `/me/accounts`. Meta documents that a Page token derived from a long-lived User token has no expiration date; verify the result in the [Access Token Debugger](https://developers.facebook.com/tools/debug/accesstoken/). Keep the app secret out of source control.
4. Keep `META_GRAPH_VERSION` at a version supported by your app. Facebook and Instagram publication in this project creates **public** Reels.

## 4. Instagram local video upload

The project uploads the local MP4 directly to Meta using the [resumable upload flow in Meta's sample app](https://github.com/fbsamples/reels_publishing_apis/blob/main/insta_reels_publishing_api_sample/README.md#resumable-upload-file-upload-upload_typeresumable). No additional video hosting account or AWS credentials are needed. The Page token still needs Instagram content publishing permission.

## Optional sources

- `PIXABAY_API_KEY` supplies automatic stock search. Sign in or register at [Pixabay's API documentation](https://pixabay.com/api/docs/) and copy the key shown there into `.env`. The app downloads candidates locally, caches search responses for 24 hours, and checks sampled frames with the local `[vision]` extra or an image-capable `STOCK_VISION_MODEL` and `LLM_API_KEY`. Accepted clips receive credits. If visual verification is unavailable, narration-based visuals are used. Restart the backend after changing `.env`.
- `PEXELS_API_KEY` also supplies stock video if you already have a key. [Pexels says new API key issuance is currently paused](https://help.pexels.com/hc/en-us/articles/900004904026-How-do-I-get-an-API-key) as of 10 October 2026. With neither key, `STOCK_FALLBACK=concept` generates narration-based visuals unless you upload a clip. Set `STOCK_FALLBACK=error` if you want generation to stop whenever no matching clip is found.
- `WIKIMEDIA_USER_AGENT` should include your contact email, website, or wiki user before relying on Wikipedia notes. [Wikimedia's policy](https://foundation.wikimedia.org/wiki/Policy%3AWikimedia_Foundation_User-Agent_Policy/en) explains the required format. You can also paste your own factual notes into the Studio.

Once the values are present, validate them without publishing first. `shorts check` confirms local configuration; an actual private YouTube upload and public Meta posts should only be run after you choose to test those accounts.
